# Guardian file-manager source fork

This is a source-review checkout, not an installed or approved file service.

Keep the upstream Apache-2.0 license and attribution. Use a branch and PR; do not push changes directly to the default branch. Preserve the pinned upstream identity recorded in the parent Guardian migration evidence.

The owner requested a real file/folder management interface integrated into Guardian. Reuse the existing upstream UI and tested operation contracts where appropriate. Do not replace the source with a cosmetic mock and call it functional. Scope actual file access through Guardian identities, root capabilities and preview/execute receipts.

All governed agent work must enter through the current tools/hoss dispatch authority. Do not bypass held BUILD, sandbox or cost prerequisites through a different checkout or provider. Exact source changes require tests and independent review before a candidate is installed.

Do not install a service, start Docker, expose a port, connect real storage, create credentials, enable public shares, invoke previews on private media, enable external document editors, or run unattended workers from this checkout. Initial runtime tests use synthetic roots and a loopback-only authenticated session after admission. Source dependencies/toolchain are not automatically admitted by cloning the repository.

All LLM models stay on NVMe. Personal photos are confined to Hossam's NAS account; other NAS home directories and shared photo space are outside this migration's write scope. Do not put private filenames, user data or machine-specific secrets into the public fork.

Inspect current advisories and prove required authentication, path confinement, stale-preview rejection, interrupted-transfer recovery and role boundaries. A fork or version number alone is not evidence of security. Keep build commands and tests bounded and stop on failed prerequisites.
